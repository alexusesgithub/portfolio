What it does

Access data is spread across HR, identity providers and individual apps, and each one has its own idea of who a user is. Access reviews usually mean exporting spreadsheets and cross-checking them by hand. ReviewPoint replaces that with one reconciled inventory and a review workflow that ends in a real access change and an audit trail.

Integrations

  • Okta, Salesforce, GitHub, Freshdesk, Frappe HRMS: identity, account and entitlement data over REST and SCIM APIs
  • Okta de-provisioning: review decisions turn into real access changes, such as group removal
  • Microsoft Teams: bot and Power Automate webhook
  • Email: notifications when a review is assigned, reminders, and overdue alerts

Reconciliation engine

The engine flags specific, named exceptions instead of a generic "review this":

TERMINATED_ACTIVE_ACCESS

Terminated users who still have access.

ORPHAN_ACCOUNT

Accounts with no linked identity.

UNLINKED_ACCOUNT

Accounts that couldn't be matched to a known identity.

DUPLICATE_IDENTITY

The same person recorded as more than one identity.

CONFLICTING_ACCESS_STATUS

Access status that disagrees between systems.

UNOWNED_SERVICE_ACCOUNT

Service accounts with no owner.

Every exception carries the evidence that produced it and opens in an Investigation Drawer, so reviewers can check the conflicting records side by side instead of taking the flag on trust.

Security & compliance

  • RBAC and AES-256 encryption
  • Immutable audit logging for every decision and action
  • Segregation of duties: no one can review their own account
  • Analyst sign-off before a review closes
  • Evidence exports to Excel and JSON for auditors

Client delivery

I ran client demos, onboarded reviewers and app owners, and deployed ReviewPoint into client environments. Reviewer feedback went straight back into the product:

  • Highlighted access changes since the last review, so reviewers see what's new
  • A simpler filters panel
  • Clearer Accept/Reject decisions

Debugging in production

  • The error that blamed the wrong thing. A failed Okta remediation told the admin their role was the problem. The real cause was an API scope Okta hadn't granted. I traced it and changed the error so it names the actual cause.
  • Syncs that stalled silently. Scheduled syncs were getting stuck behind data sources that could never start. I fixed the stall and added live sync progress, so a stuck sync is now visible.
