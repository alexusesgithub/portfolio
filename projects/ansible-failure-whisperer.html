Overview

Ansible and AWX are core to how Sennovate automates infrastructure and security operations, but when a job fails, the output is a wall of module tracebacks and host-level errors that takes real effort to parse — especially for anyone who isn't the person who wrote the playbook. I built a tool that reads that raw failure output and returns a short, accurate, plain-English explanation of what actually went wrong.

The Problem

Automation failures are frequent enough to be a real time cost, and the people triaging them aren't always the ones who wrote the playbook. The failure signal is there in the logs, but it's buried:

  • AWX job output mixes module internals, retries, and the actual failure reason together.
  • Diagnosing a failure often meant re-reading logs line by line to find the one that mattered.
  • Sending logs to an external LLM API wasn't acceptable — this is infrastructure and security-adjacent data that needed to stay on-prem.

Approach

Rather than treating this as "point a chatbot at the logs," I built a focused diagnostics pipeline: extract the failed task and relevant log context, construct a targeted prompt around it, and run inference locally against Qwen 3.5B so no failure data — some of which touches security and access systems — ever leaves the network.

Key Challenges

  • Running a useful model locally — local inference means a smaller model and tighter latency/quality tradeoffs than a hosted frontier LLM; prompt design had to do more of the work.
  • Extracting the right log context — AWX output is verbose; picking the slice that actually explains the failure (without truncating the real cause) mattered more than the model itself.
  • Keeping explanations trustworthy — a confident-sounding wrong answer is worse than no answer, so outputs needed to stay grounded in what the logs actually showed.

Outcome

The tool cuts down the time engineers spend manually reading AWX failure logs, and keeps that diagnostic step entirely on local infrastructure — no automation or security-adjacent data goes to an external API.
